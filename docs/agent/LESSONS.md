# Lessons

使用者糾正轉成可執行規則，最新放最上方。只記跨任務仍有用的行為，不複製單一頁面的像素規格或已能從程式碼直接看出的事實。

## 2026-10-14

- 當既有雙語網站接入Shopify時，先盤點已核准中文並遷入Shopify翻譯／CMS欄位；不能因Shopify尚無翻譯就讓中文頁退回英文，也不能把本來有的文案列成待使用者補齊。價格和庫存仍以Shopify為準。

- 當使用者指定「Visual 照片、Shopify 商品資料」兩個來源時，分別維護影像與商品身分對照；價格、庫存、規格依 Shopify，照片依已核准 Visual。用 variant 身分配圖，不用陣列順序，也不把舊前台預購額度反寫商店。

## 2026-10-13

- 當做新禮盒的商品圖時，一開始就拿網站同一視角的現有商品圖（例如 `listing-tea-spring-dawn-*-even2`、`studio-*-end-angle-even2`、`gift-box-unboxed-12-v2-even2`）當構圖＋光影＋影子參考，提示詞寫明「明亮高調、大面積柔光、淺暖灰底無暗角、影子淡而往右下漸淡、盒底無黑邊」；不要自己寫「靠盒底最深」這類硬影子。正規化一律用 `norm.py` 的 0.45（網站現行值），交付前和網站同類圖並排比大小、影子與底色（使用者：「影子都處理得很醜！！！不要再犯」）。
- 當用客戶近拍的實拍照（正面、開箱）做圖庫時，先檢查鏡頭變形（外盒變梯形、看不到側面）；要透視校正成長方形再去背，否則外盒會像一張紙板（使用者：「盒子外盒也有問題」）。
- 當要填客戶還沒給的價格時，不要自己推算數字放上網站；用「價格待訂／Price to be announced」並停用購物按鈕（使用者：「US$130 幫我用價格代訂，不要自己亂寫」）。其他推理的暫定事實要在資料旁註明待客戶確認。

## 2026-10-12

- 當使用者給的參考圖是手機或網頁截圖時，先裁掉按鈕、圖示等介面元素再交給 AI；否則 AI 會把「造訪網站」之類的按鈕畫進成品。
- 當畫茶標時，它是扁平薄片（像紙一樣平貼）、兩端直線切口加細橫紋、沒有鋸齒，也不是鼓起的條狀包；長度約等於杯身寬度。AI 常畫成鼓起的長條包，交付前放大檢查這三點（使用者：「不要再讓我提醒一次！」）。
- 當用程式替商品照加陰影或換背景時，模糊前四周要留白（不然陰影會被切成硬長方形），並排除「只變暗、顏色不變」的投影像素，不要把投影當成商品；交付前放大看陰影邊緣。
- 當生成或修改含茶標的情境照時，先量茶標長度與杯口直徑的比例（約 0.85 倍），超過就不能交付；也要對照真實道具（例如熱水壺把手位置）是否合理。
- 當畫面出現 CHARM VILLA 茶標時，材質是霧面金，不要像鏡子或亮面鋁箔；實拍上的亮光只是打光。提示詞要寫 matte gold、no mirror shine，交付前放大檢查。
- 當使用者指定新商品照放在「圖二」但未指示取代時，新增為第二個縮圖，原圖往後順移；不可自行刪除原本圖二。保留首圖與清單封面。實拍應與現行棚拍底色一致，以淺灰背景承接；統一產品顯示比例、維持留白並以 contain 避免裁切盒型與蝴蝶結。
- 當呈現 CHARM VILLA 茶標時，棉線應從邊緣進入並黏在折疊紙層內；茶標不可打洞，不加金屬孔眼，也不把棉線穿過紙面。用使用者的實拍標籤檢查比例與字樣。
- 當使用者要求小金魚茶包的沖泡情境時，杯中必須呈現實物參考的金魚茶包；不得以只有清水的倒水畫面代替。先看泡開後的實拍，並檢查袋身、尾鰭與棉線幾何。
- 當同一購物車出現不同幣別時，應分幣別列出小計；沒有核准匯率與市場規則，不得直接相加或自行換算。
- 當使用者標示特定文字層級調整字級時，只改該層級；標題、編號、按鈕與未被標示的層級維持不動，並用 computed style 驗證。
- 當內容來源無法追溯到核准文件時，應清楚標為未確認；不得把 agent 撰寫或外部背景資料說成品牌核准文案。
- 當使用者要求 Preview 網址時，應建立並線上驗證 Preview；除非另外明確授權，不得把 Preview、Production、Git commit 與 Git push 混為同一件事。
- 當使用者提供參考網站時，應學習版型、節奏與互動原理，再轉譯為 CHARM VILLA 的品牌語彙；不得複製參考站商標、文案、影像或程式。
- 當既有核准圖片只需要更聚焦時，應先調整裁切與呈現；不得未經指示換成另一張素材或生成圖。
