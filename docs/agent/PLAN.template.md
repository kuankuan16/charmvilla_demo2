# Agent Plan Template

這是格式參考，不是目前任務。將必要欄位填進 [PLAN.md](PLAN.md)；開始新任務前先保留未交付工作與 queue，不可直接覆蓋。

Status: `in_progress | waiting | completed`（擇一）
Updated: YYYY-MM-DD

- 已授權動作與目標環境：
- 修改範圍／不在本輪的範圍：
- Git 基準、分支、工作樹與既有未提交變更：
- 可觀察的完成條件：
- 尚待回答的必要問題（沒有就寫「無」）：

## Steps and evidence

| 狀態 | 動作 | 如何證明完成 | 實際結果／證據 |
| --- | --- | --- | --- |
| pending | 先重現問題或核對資料來源 | 寫明具體頁面、輸入與預期 | 尚未執行 |
| pending | 在限定檔案做最小修改 | 寫明行為差異與檢查命令 | 尚未執行 |
| pending | 重跑原路徑並驗證影響範圍 | 依 VERIFY.md 選必要檢查 | 尚未執行 |

步驟狀態用 `pending`、`in_progress`、`completed` 或 `blocked`；完成要附證據，不能只改狀態。

## Attempts and decisions

沒有失敗則寫「無」。同一步驟連續失敗兩次後先重規劃，不要盲試第三次。

| 步驟／第幾次 | 操作與觀察 | 已排除／新假設 | 下一個區別性檢查 |
| --- | --- | --- | --- |

需要取捨時簡記 UX、DX、AX 影響與選擇原因，不另寫無法驗證的長篇推測。

## Verification and delivery

- 已執行：命令或操作、環境、結果、證據位置。
- 未執行：項目、原因與對完成條件的影響。
- 必要完成條件若未滿足，維持未完成狀態；不能用限制說明代替驗證。
- 交付狀態：本機／Git commit／push／Preview／Production 分開記錄，沒有就明寫未執行。
- 仍待外部事件的限制：列事實，不自行轉為新任務。

- 必要連結或經遮蔽的證據：

完成並交付後，先接 FIFO 第一項；queue 為空則保留本次精簡結果，等待下一個使用者指示。
